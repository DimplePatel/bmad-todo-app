# Story E1.S1 — Initialize monorepo & tooling

**Epic:** E1 — Project Foundation & Health
**Status:** Ready for Dev
**Estimate:** S
**Traces to:** PRD NFR5 (maintainability), NFR6 (test coverage tooling)

## User story
> As a developer, I want a typed monorepo with linting, formatting, and test runners wired up, so that all subsequent stories build on consistent tooling.

## Context
First story of the project. Establishes the workspace layout in `docs/architecture.md` §3 and the toolchain referenced by every other story.

## Acceptance criteria
1. Root `package.json` declares workspaces: `backend`, `frontend`, `packages/shared`, `e2e`.
2. TypeScript configured in each workspace; `tsconfig.base.json` at the root with `strict: true`.
3. ESLint + Prettier configured at the root with shared config; `npm run lint` from the root succeeds.
4. Vitest installed in `backend` and `frontend`; one placeholder test in each passes via `npm test --workspace=...`.
5. Playwright installed in `e2e/` with `playwright.config.ts`; `npx playwright test --list` runs without error.
6. Root `README.md` quick-start describes install / lint / test / dev commands.

## Technical notes
- Use `npm` workspaces (not pnpm) for simplicity.
- ESLint flat config (`eslint.config.mjs`) shared via root + per-workspace extension.
- `tsconfig.base.json` enables `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`.

## Test strategy

### Unit tests
- **U1.** `backend/tests/unit/sanity.test.ts` — `expect(1 + 1).toBe(2)` to confirm Vitest runs.
- **U2.** `frontend/src/__tests__/sanity.test.tsx` — RTL renders `<div>hello</div>` and asserts text.

### Integration tests
- _None for this story._

### E2E tests (Playwright)
- **E1.** `e2e/tests/smoke.spec.ts` — placeholder test that asserts `expect(true).toBe(true)`. Confirms Playwright executes; will be replaced in E4.S5.

### Verification commands
```
npm install
npm run lint
npm test --workspaces
npx --workspace=e2e playwright test --list
```

## Definition of Done
- All ACs met; CI-friendly commands listed in README work on a clean clone.
