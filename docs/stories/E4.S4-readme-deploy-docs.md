# Story E4.S4 — README + deploy docs

**Epic:** E4 — Polish, A11y & Deploy Readiness
**Status:** Ready for Dev
**Estimate:** S
**Traces to:** PRD §9 DoD; Architecture §9

## User story
> As a developer evaluating or deploying this app, I want a clear README and deploy notes, so that I can run, test, and ship it without guesswork.

## Acceptance criteria
1. Root `README.md` includes:
   - Prerequisites (Node 20+, Docker).
   - Local dev without Docker (per workspace).
   - Local dev with Docker (`docker compose up --build`).
   - How to run unit, integration, and Playwright E2E tests.
   - Env vars (`PORT`, `DATABASE_PATH`, `CORS_ORIGIN`, `NODE_ENV`) with defaults.
   - "Deploy anywhere" section explaining the named volume contract and a generic deploy outline.
   - A short "Architecture at a glance" with an ASCII diagram.
2. `.env.example` files exist at the root (compose) and in `backend/` (app config).
3. README references `docs/architecture.md`, `docs/prd.md`, `docs/test-strategy.md`, and the `docs/epics/` folder.

## Technical notes
- Keep prose under ~800 lines; long material lives in `docs/`.

## Test strategy

### Unit tests
- _Markdown lint via `markdownlint-cli2` (CI step) on `README.md` and `docs/**/*.md`._

### Integration tests
- **I1.** "Cold-clone" smoke (CI): a fresh clone runs `docker compose up --wait`; the health endpoint returns `200`.

### E2E tests (Playwright)
- _Not applicable (docs-only)._

### Verification commands
```
npx markdownlint-cli2 "**/*.md"
docker compose up --wait
curl http://localhost:5173/api/health
```

## Definition of Done
- ACs met; a teammate (or the QA persona) follows the README on a clean machine and reaches a working app.
