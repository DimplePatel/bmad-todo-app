# Story E3.S6 — Items-left counter and "Clear completed"

**Epic:** E3 — Frontend Todo Experience
**Status:** Ready for Dev
**Estimate:** S
**Traces to:** PRD FR8, FR15

## User story
> As a user, I want a count of remaining tasks and a quick way to clear finished ones, so that the list stays focused.

## Acceptance criteria
1. The footer shows `"N items left"` where N is the count of `completed=false` todos. Pluralization handled (`"1 item left"`).
2. A `Clear completed` button is visible only when ≥ 1 completed todo exists.
3. Clicking the button calls `DELETE /api/todos?completed=true`, optimistically removes all completed rows, and on failure restores them with an error toast.
4. The button has an accessible name and is reachable by keyboard.

## Technical notes
- Mutation invalidates the `["todos"]` cache or merges the optimistic list into it.

## Test strategy

### Unit tests
- **U1.** Footer renders correct counter for 0, 1, and many active todos.
- **U2.** `Clear completed` button visibility toggles based on completed-count.

### Integration tests (RTL + MSW)
- **I1.** With 2 completed + 3 active, click `Clear completed` → optimistically only 3 rows visible; on success, MSW saw the bulk delete request.
- **I2.** Failure rollback: MSW 500 → all rows restored, toast shown.

### E2E tests (Playwright)
- **E1.** Step in `happy-path.spec.ts`: create 3 todos, complete 2, click `Clear completed`, assert only 1 row remains; reload, assert it persists.

### Verification commands
```
npm test --workspace=frontend -- footer
```

## Definition of Done
- ACs met; pluralization verified; bulk-delete flow verified end-to-end.
