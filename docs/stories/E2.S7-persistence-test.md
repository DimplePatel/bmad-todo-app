# Story E2.S7 — Persistence across restart

**Epic:** E2 — Backend CRUD API & Persistence
**Status:** Ready for Dev
**Estimate:** S
**Traces to:** PRD NFR2; Architecture §9, R5 mitigation

## User story
> As a developer, I want a test that proves data survives a backend restart, so that NFR2 is verified and regressions are caught.

## Acceptance criteria
1. An integration test:
   - Builds the app against a temp DB file path,
   - Creates 3 todos via the API,
   - Disposes the app instance,
   - Builds a new app against the **same** DB file,
   - Asserts `GET /api/todos` returns the same 3 todos.
2. The test cleans up the temp file in `afterAll`.

## Technical notes
- Don't rely on the OS process lifecycle; calling `buildApp()` twice against the same file is sufficient and faster than spawning processes.
- For an extra-strong guarantee in CI, an optional Compose-level test brings the backend container down and back up; out of scope here unless trivially achievable.

## Test strategy

### Unit tests
- _None._

### Integration tests
- **I1.** `tests/integration/persistence.test.ts` — implements the AC above.

### E2E tests (Playwright)
- _Covered separately in E4.S5 by reloading the page after creating todos._

### Verification commands
```
npm test --workspace=backend -- persistence
```

## Definition of Done
- AC met; test runs in < 1 s; failure mode (e.g., wrong DB path) reliably trips the test.
