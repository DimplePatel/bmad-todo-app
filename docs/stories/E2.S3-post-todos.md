# Story E2.S3 — `POST /api/todos`

**Epic:** E2 — Backend CRUD API & Persistence
**Status:** Ready for Dev
**Estimate:** S
**Traces to:** PRD FR1, FR2, FR13; Architecture §4.3, §6

## User story
> As a user, I want to create a todo, so that I can capture a task.

## Acceptance criteria
1. Request body validated against `CreateTodoBody` (Zod): `title` is `string`, trimmed, length 1–200.
2. On success, returns `201` with the new `Todo` (server-generated `id`, `createdAt`, `updatedAt`; `completed=false`).
3. Empty/whitespace-only titles return `400` with `{ "error": "Invalid request", "issues": [...] }`.
4. Title longer than 200 characters returns `400`.
5. Non-JSON or oversize body (>16 KB) returns `400`.
6. Logs one structured line with `status: 201` (or `400`) and `duration_ms`.

## Technical notes
- Service layer trims the title before calling the repository.
- Validation errors throw `HttpError(400, "Invalid request", issues)`; the central error handler renders them.

## Test strategy

### Unit tests
- **U1.** `todos.schema.test.ts` — Zod schema accepts a 1-char title, rejects empty / whitespace / 201-char title.
- **U2.** `todos.service.create.test.ts` — trims the title, calls `repo.create({ title: trimmed })`.

### Integration tests
- **I1.** Happy path: `POST /api/todos { title: "  buy milk  " }` returns `201` with a body that has trimmed title `"buy milk"`, `completed=false`, valid UUID, ISO timestamps.
- **I2.** Empty title → `400` with `issues[0].path === ["title"]`.
- **I3.** Whitespace-only title → `400`.
- **I4.** Title > 200 chars → `400`.
- **I5.** Body is not JSON → `400`.
- **I6.** Oversize body (>16 KB) → `400`.
