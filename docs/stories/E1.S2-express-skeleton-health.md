# Story E1.S2 — Express backend skeleton with `/api/health`

**Epic:** E1 — Project Foundation & Health
**Status:** Ready for Dev
**Estimate:** S
**Traces to:** PRD NFR10 (observability), Architecture §4.2, §4.6

## User story
> As a developer, I want a minimal Express server in TypeScript with a health endpoint, so that I can verify the backend boots correctly and other services can probe it.

## Context
Establishes the backend skeleton, the `buildApp(deps)` factory, and the request logger used by every subsequent backend story.

## Acceptance criteria
1. `backend/src/index.ts` boots an Express app on `PORT` (default `3001`).
2. `backend/src/app.ts` exports a `buildApp(deps)` function returning a configured `Express` instance (testable without listening).
3. `GET /api/health` returns `200` with body `{ "status": "ok" }`.
4. A request logger middleware writes one JSON line per request to stdout with `ts`, `level`, `method`, `path`, `status`, `duration_ms`.
5. `helmet`, `cors`, and `express.json({ limit: "16kb" })` middlewares are wired (full hardening lives in E4.S3, but they exist now).
6. `npm run dev --workspace=backend` starts the server with hot reload (tsx/ts-node-dev).

## Technical notes
- `buildApp` takes a `deps` object so the repository can be injected in tests later.
- `index.ts` should call `buildApp({ repo: ... })` even though `repo` is a no-op stub in this story; satisfies dependency-injection shape now.
- Use `pino` or `console.log` JSON; either is fine in v1.

## Test strategy

### Unit tests
- **U1.** Logger middleware: invoking it with a fake `req`, `res`, `next` triggers a single JSON write with the expected keys.

### Integration tests
- **I1.** `tests/integration/health.test.ts` (Supertest):
  - **Given** the app built with `buildApp({ repo: stub })`,
  - **When** `GET /api/health` is requested,
  - **Then** status is `200` and the JSON body equals `{ "status": "ok" }`.
- **I2.** Logger emits a line on a successful request (capture `process.stdout.write` and assert one JSON line with `path: "/api/health"` and `status: 200`).

### E2E tests
- _Deferred to E1.S4 (Compose stack) and E4.S5 (full suite)._

### Verification commands
```
npm test --workspace=backend
npm run dev --workspace=backend
curl http://localhost:3001/api/health
```

## Definition of Done
- All ACs met; integration tests green; manual `curl` returns the expected JSON.
