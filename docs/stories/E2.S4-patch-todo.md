# Story E2.S4 — `PATCH /api/todos/:id`

**Epic:** E2 — Backend CRUD API & Persistence
**Status:** Ready for Dev
**Estimate:** S
**Traces to:** PRD FR4, FR13, NFR8; Architecture §4.3, §6

## User story
> As a user, I want to toggle a todo's completion (and, future-proof, edit its title), so that I can track progress.

## Acceptance criteria
1. Body validated against `UpdateTodoBody`: `completed?` boolean, `title?` string (trimmed, 1–200), at least one field required.
2. On success, returns `200` with the updated `Todo` (refreshed `updatedAt`).
3. Returns `404` if `:id` does not exist.
4. Returns `400` if the body is empty or fields fail validation.
5. `:id` is validated as a UUID; invalid `id` returns `400`.
6. Logs one structured line with the resulting status.

## Technical notes
- Repository's `update` returns the new row or `null`; controller maps `null` → `404`.
- Even though title editing isn't exposed in the v1 UI, this endpoint supports it now to avoid breaking changes later.

## Test strategy

### Unit tests
- **U1.** `todos.schema.update.test.ts` — accepts `{ completed: true }`, `{ title: "x" }`, `{ title: "x", completed: true }`; rejects `{}`.
- **U2.** `todos.service.update.test.ts` — trims `title` when present, propagates `completed` unchanged.

### Integration tests
- **I1.** Toggle completion happy path → `200`, body has `completed=true` and `updatedAt > createdAt`.
- **I2.** Update title happy path → `200`, body has trimmed title.
- **I3.** Empty body → `400`.
- **I4.** Invalid `:id` (non-UUID) → `400`.
- **I5.** Unknown `:id` → `404`.
- **I6.** `title` > 200 chars → `400`.

### E2E tests (Playwright)
- _Covered via E3.S3 toggle flow and E4.S5 happy path._

### Verification commands
```
npm test --workspace=backend -- todos.update
curl -X PATCH -H 'content-type: application/json' \
  -d '{"completed":true}' http://localhost:3001/api/todos/<id>
```
