# Story E3.S7 — Error toast + retry pattern

**Epic:** E3 — Frontend Todo Experience
**Status:** Ready for Dev
**Estimate:** S
**Traces to:** PRD FR11, NFR4

## User story
> As a user, I want clear, non-blocking feedback when something goes wrong, so that I can keep working.

## Acceptance criteria
1. A reusable `<ToastHost />` is mounted at the app root and consumes a toast queue.
2. All API failures surface a toast with: a human-readable message, a `Retry` affordance that reissues the failed mutation, and a `Dismiss` action.
3. Toasts auto-dismiss after 5 s unless interacted with (hover/focus pauses dismissal).
4. Toast container has `role="status"` and is announced to screen readers; messages do not trap focus.
5. Retrying twice in a row re-runs the underlying mutation each time; the toast updates to reflect new outcomes.

## Technical notes
- Toast queue is a small Zustand-style store or React context; each toast carries an optional `onRetry` callback.

## Test strategy

### Unit tests
- **U1.** Toast auto-dismisses after 5 s.
- **U2.** Hovering pauses dismissal; mouse-out resumes the timer.
- **U3.** `Retry` invokes the supplied callback exactly once per click.

### Integration tests (RTL + MSW)
- **I1.** `POST /api/todos` 500 → toast appears; clicking Retry re-issues `POST` (MSW count = 2).
- **I2.** Multiple concurrent failures stack as multiple toasts (independent dismiss timers).

### E2E tests (Playwright)
- **E1.** `e2e/tests/error-rollback.spec.ts`:
  - Block `POST /api/todos` with `route.fulfill({ status: 500 })` for the first request; restore for the second.
  - Type a todo, press Enter → toast visible with Retry → click Retry → todo appears.

### Verification commands
```
npm test --workspace=frontend -- toast
npx playwright test e2e/tests/error-rollback.spec.ts
```

## Definition of Done
- ACs met; retry, auto-dismiss, hover-pause, and a11y semantics verified.
