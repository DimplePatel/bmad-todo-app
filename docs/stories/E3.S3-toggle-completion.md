# Story E3.S3 — Toggle completion (optimistic)

**Epic:** E3 — Frontend Todo Experience
**Status:** Ready for Dev
**Estimate:** S
**Traces to:** PRD FR4, FR5, FR11, NFR1; Architecture §7.4

## User story
> As a user, I want to mark a todo done with one click, so that I can update status quickly.

## Acceptance criteria
1. A real `<input type="checkbox">` toggles `completed`; the row updates optimistically (strikethrough + dimmed text).
2. On API success, the response replaces the optimistic state.
3. On API failure, the toggle reverts and an error toast with Retry is shown.
4. Completion is also indicated by a non-color cue (strikethrough); color contrast meets WCAG 2.1 AA in both states.

## Technical notes
- Mutation invokes `PATCH /api/todos/:id { completed }`.
- Cache update mutates the entry in the `["todos"]` cache by id.

## Test strategy

### Unit tests
- **U1.** `<TodoItem />` renders the strikethrough class when `completed=true`; checkbox is `aria-checked` accordingly.

### Integration tests (RTL + MSW)
- **I1.** Toggle on → row visually completes immediately; on success, state matches server.
- **I2.** Toggle off → row reverts to active.
- **I3.** Failure rollback: MSW 500 → checkbox reverts, toast shown.

### E2E tests (Playwright)
- **E1.** In `happy-path.spec.ts`: after creating a todo, click its checkbox → assert it has the `completed` accessible state and styling.

### Verification commands
```
npm test --workspace=frontend -- TodoItem
```

## Definition of Done
- ACs met; rollback verified; a11y check confirms checkbox semantics.
