# Story E2.S2 — `GET /api/todos`

**Epic:** E2 — Backend CRUD API & Persistence
**Status:** Ready for Dev
**Estimate:** S
**Traces to:** PRD FR3, NFR1, NFR9; Architecture §6

## User story
> As a user (or the frontend), I want to retrieve all todos in newest-first order, so that the list view can render the user's tasks.

## Acceptance criteria
1. `GET /api/todos` returns `200` with a JSON array of `Todo` sorted by `createdAt desc`.
2. Returns `[]` when the table is empty.
3. Response shape matches the `Todo` type exactly (no extra columns leaked).
4. Logs one structured request line with `status: 200` and `duration_ms`.

## Technical notes
- Controller delegates to `service.list()`, which returns `repo.list()` directly (no business rules to apply).
- No pagination in v1.

## Test strategy

### Unit tests
- **U1.** `todos.controller.list.test.ts` — calls service mock and writes `200` with the returned array.
- **U2.** `todos.service.list.test.ts` — passes through to repo mock.

### Integration tests
- **I1.** `tests/integration/todos.list.test.ts` (Supertest):
  - **Given** an app built with a temp-file repository and three seeded todos with distinct `createdAt`,
  - **When** `GET /api/todos`,
  - **Then** status is `200`, body has length 3, and items are ordered by `createdAt desc`.
- **I2.** Empty-list case: returns `200` with `[]`.
