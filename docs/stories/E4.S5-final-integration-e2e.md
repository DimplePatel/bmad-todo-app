# Story E4.S5 — Final integration + Playwright E2E suite

**Epic:** E4 — Polish, A11y & Deploy Readiness
**Status:** Ready for Dev
**Estimate:** M
**Traces to:** PRD NFR2, NFR6; Architecture §8

## User story
> As a maintainer, I want a comprehensive Playwright E2E suite and a passing coverage gate, so that v1 is shippable with confidence.

## Acceptance criteria
1. Playwright suite under `e2e/tests/` includes at minimum:
   - `happy-path.spec.ts` — create, complete, delete, clear completed.
   - `filter-persistence.spec.ts` — selected filter survives reload.
   - `undo-delete.spec.ts` — undo within 5 s; deletion sticks after 5 s.
   - `error-rollback.spec.ts` — server 500 triggers rollback + retry toast.
   - `a11y.spec.ts` — axe scan with 0 serious/critical violations.
   - `responsive.spec.ts` — viewport sweep (no horizontal scroll).
2. Backend line coverage report shows ≥ 80% (`npm test --workspace=backend -- --coverage`).
3. Persistence integration test (E2.S7) green.
4. Single root command: `npm run e2e` runs Playwright against the Compose stack and exits non-zero on any failure.
5. CI artifact: Playwright HTML report uploaded.

## Technical notes
- `playwright.config.ts` `webServer` runs `docker compose up --wait` (or assumes the stack is up in CI) and waits on `http://localhost:5173`.
- Each test resets server state via `request.delete('/api/todos?completed=true')` and a follow-up sweep that deletes any remaining via the API in `beforeEach` (helper).

## Test strategy

This story IS the test strategy. ACs above enumerate the scenarios.

### Verification commands
```
docker compose up --wait
npm run e2e
npm test --workspace=backend -- --coverage
```

## Definition of Done
- All ACs met; coverage gate ≥ 80%; CI publishes the Playwright HTML report; v1 is shippable.
