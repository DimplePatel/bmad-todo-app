# Story E3.S5 — Filter (All / Active / Completed) with persistence

**Epic:** E3 — Frontend Todo Experience
**Status:** Ready for Dev
**Estimate:** S
**Traces to:** PRD FR7

## User story
> As a user, I want to focus on active or completed todos, so that I can declutter my view.

## Acceptance criteria
1. Three filter chips: `All`, `Active`, `Completed`. Current filter is visually emphasized and is the only one with `aria-pressed="true"`.
2. The selected filter is persisted to `localStorage` (key: `todo.filter`) and restored on next load.
3. Filtering is purely client-side over the already-fetched list.
4. If the persisted value is invalid or missing, the default is `All`.

## Technical notes
- Tiny store in `state/filterStore.ts` that wraps `localStorage` with a typed get/set; provides a React hook `useFilter()` returning `[filter, setFilter]`.

## Test strategy

### Unit tests
- **U1.** `filterStore.test.ts` — round-trips a value; ignores invalid values; falls back to `All`.

### Integration tests (RTL)
- **I1.** Default render shows All chip pressed; clicking Active hides completed rows.
- **I2.** Reload (re-render with fresh provider) restores the previously selected filter.

### E2E tests (Playwright)
- **E1.** `e2e/tests/filter-persistence.spec.ts`:
  - Create one active and one completed todo.
  - Click `Active` → assert only active row is visible.
  - Reload the page → assert `Active` is still selected and only active row is visible.

### Verification commands
```
npm test --workspace=frontend -- filter
npx playwright test e2e/tests/filter-persistence.spec.ts
```

## Definition of Done
- ACs met; persistence verified across page reload.
