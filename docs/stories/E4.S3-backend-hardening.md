# Story E4.S3 — Backend hardening (security baseline + observability)

**Epic:** E4 — Polish, A11y & Deploy Readiness
**Status:** Ready for Dev
**Estimate:** S
**Traces to:** PRD NFR9, NFR10; Architecture §4.6, §4.7

## User story
> As an operator, I want sensible default headers, a strict CORS policy in production, and structured request logs, so that the service is safe to expose and debuggable.

## Acceptance criteria
1. `helmet()` middleware is enabled with default settings; an integration test asserts `Content-Security-Policy` and `X-Content-Type-Options: nosniff` are present.
2. CORS is configured via `CORS_ORIGIN` env var; in `NODE_ENV=production`, `*` is rejected at startup with a clear error.
3. Request logger emits one JSON line per request with `ts`, `level`, `method`, `path`, `status`, `duration_ms`.
4. Error handler logs unexpected exceptions at `level: "error"` with stack trace, but never returns the stack in the HTTP body.
5. JSON body size cap (`16 KB`) is enforced; oversize body returns `400` with a clear message.

## Technical notes
- Don't use `cors({ origin: '*' })` even in dev unless explicitly opted in via `NODE_ENV=development`.

## Test strategy

### Unit tests
- **U1.** `config.test.ts` — parsing `NODE_ENV=production CORS_ORIGIN=*` throws.
- **U2.** Logger formatter — emits exactly one JSON line per call with required fields.

### Integration tests
- **I1.** Helmet headers present on responses.
- **I2.** CORS preflight from an allowed origin returns the appropriate `Access-Control-Allow-Origin`.
- **I3.** CORS from a disallowed origin in production rejects (no allow-origin header).
- **I4.** 17 KB body returns `400`.
- **I5.** Triggering an internal exception returns `500` with `{ "error": "Internal server error" }` and no stack in the body; stderr contains the stack.

### E2E tests (Playwright)
- _Implicit; covered by a11y/happy-path running against the Compose stack._

### Verification commands
```
npm test --workspace=backend -- security
```

## Definition of Done
- ACs met; production config rejects `*`; oversize body and exception paths verified.
