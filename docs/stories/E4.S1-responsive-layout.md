# Story E4.S1 — Responsive layout (320 px → 1920 px)

**Epic:** E4 — Polish, A11y & Deploy Readiness
**Status:** Ready for Dev
**Estimate:** S
**Traces to:** PRD NFR3

## User story
> As a user, I want the app to look and feel right on whatever device I use, so that I can manage tasks anywhere.

## Acceptance criteria
1. The list renders cleanly at 320 px wide; no horizontal scroll; touch targets ≥ 44 × 44 px.
2. At desktop widths, content is constrained to a readable column (max-width ~640 px) and centered.
3. Buttons and chips wrap reasonably on narrow viewports; nothing overflows or clips.
4. Tested across these viewports: 320, 375, 768, 1280, 1920 px.

## Technical notes
- Use simple CSS with `clamp()` for type and `min(640px, 100% - 32px)` for the column.

## Test strategy

### Unit tests
- _Visual styles aren't unit-tested; rely on E2E viewport sweeps._

### Integration tests
- **I1.** RTL test on key components at default viewport remains green; no regressions.

### E2E tests (Playwright)
- **E1.** `e2e/tests/responsive.spec.ts`:
  - For each viewport in `[320, 375, 768, 1280, 1920]`:
    - Navigate to `/`.
    - Assert no horizontal scroll: `await page.evaluate(() => document.documentElement.scrollWidth <= document.documentElement.clientWidth)`.
    - Take a screenshot for visual review (uploaded as a CI artifact).

### Verification commands
```
npx playwright test e2e/tests/responsive.spec.ts
```

## Definition of Done
- ACs met; no horizontal scroll at any tested viewport; CI uploads screenshots for QA review.
